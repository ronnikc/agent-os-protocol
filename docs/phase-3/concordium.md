# Concordium review and upstream PR specifications

[Phase 3 plan](README.md) · [Cross-repo delivery](delivery.md)

Prepare these as code, tests and runnable examples in separate branches or forks against the confirmed public base revisions. Use repository-native types, fixture style and test commands. Prepare the actual PR body with pinned revisions, dependency order, independent repro, compatibility and rollback. Open upstream PRs when the owner authorizes submission. Maintain the evidence index in Agent OS.

## Decisions requested

1. Confirm the standard external-evidence-to-IDP issuance path and reviewer for identity and Local Stack. Confirm a compatible SDK, Base, node, connector and verifier release or test pin for genesis-bound interoperability. Existing identifiers retain their compatibility path.
2. Confirm the supported network and registry instances for a zero-balance owner using Concordium's official Agent Registry sponsor. Confirm eligibility for register and post-mint Agent Card update, and any limits or unsupported operations. Ask the existing service owner about actual gaps after an observed failure. See [registry sponsorship](pilot-contract.md#official-registry-sponsorship).
3. Review a separate Web3 ID credential example and an rCuK SDK restore example. Confirm current credential status, wallet provisioning and restore support and preferred upstream targets. Evaluate wallet or protocol changes only for gaps reproduced by the examples.
4. Record the exact review and release window if SDK/example delivery can coordinate with P11. Native issuance on the existing protocol and Phase 2 PLL activation retain independent gates.
5. Review the [origin-ID native recovery authority](origin-id-lifecycle.md#candidate-authority-model) against CC-7's current-node conformance results. Decide same-account replacement including index 0, enforceable recovery permissions, new identity-proof material, service/quorum trust, recovery-policy updates and a payer for non-registry operations. Seek a release-scope decision after early feasibility without waiting for the final CMP pilot.

Prepare CC-7 conformance and RFC early after the baseline and seek its release-scope decision alongside the other upstream work. CC-4 stays conditional on an agreed requirement and design. The existing registry and sponsor are integration targets. Open a service patch only after the service owner confirms the repository and an observed capability gap.
